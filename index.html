เริ่มตรงนี้

อ่านบทนี้ก่อนลงมือ จะได้รู้ว่าปลายทางคืออะไร ต้องมีโปรแกรมอะไรในเครื่องบ้าง และโค้ดแต่ละไฟล์ใน template ส่งต่อข้อมูลกันอย่างไร

🎯 Learning Objectives

  • ตรวจว่าเครื่องตัวเองมีโปรแกรมครบ 4 อย่างก่อนเริ่ม
  • อธิบายลำดับการทำงาน Router → Service → Repository → Database ได้

เล่มนี้เหมาะกับใคร

เล่มนี้เขียนให้คนที่พลาดคาบบางคาบ หรือเข้าเรียนแล้วแต่ตามไม่ทัน ในสัปดาห์ต่อฐานข้อมูล (Database Connection) สัปดาห์ Express และสัปดาห์ Error Handling ทุกขั้นเขียนเป็นข้อ ๆ ว่ากดอะไรแล้วจะเห็นอะไร พร้อมภาพหน้าจอจริง ถ้าทำตามลำดับตั้งแต่บทที่ 1 ถึงบทที่ 4 ตอนจบจะมี

  • โปรเจกต์ Express ที่สร้างจาก template ของรายวิชา รันได้ที่ http://localhost:3000
  • ฐานข้อมูล sakila ใน MySQL ของเครื่องตัวเอง
  • API ของตาราง country ครบ 5 เส้น คือ ดูทั้งหมด ดูทีละตัว เพิ่ม แก้ และลบ
  • error ทุกแบบตอบกลับเป็น JSON พร้อม status code ที่ถูกต้อง ไม่ใช่หน้า HTML
  • ชุด request ทดสอบใน Postman ครบทุกเส้น (เก็บเป็น Collection ได้ถ้า Sign in)

บทสุดท้ายสรุปว่าการใส่ error handler ต้องแก้ตรงไหนบ้าง พร้อมแบบฝึกทำ resource actor เอง

โปรแกรมใช้ทำอะไรตรวจว่ามีแล้วหรือยัง
WebStorm เขียนโค้ด รันโปรแกรม และเปิดดูฐานข้อมูล (มีเครื่องมือ Database ในตัว) เปิดโปรแกรมได้ นักศึกษาใช้สิทธิ์ฟรีของ JetBrains ได้
Node.js ตัวรันโค้ด JavaScript ฝั่ง server มี npm มาด้วย พิมพ์ node -v ใน Terminal ควรได้ v18 ขึ้นไป (Express 5 ต้องใช้ Node 18+)
MySQL Server ระบบฐานข้อมูลที่เก็บ sakila MySQL ต้องเปิดทำงานอยู่ และต้องจำรหัสผ่านของ user root ได้
Postman ส่ง request ไปทดสอบ API ใช้แอปแบบติดตั้งลงเครื่อง (desktop) เพราะเรียก localhost ได้ทันที ถ้าจะบันทึก request เก็บเป็น Collection ต้อง Sign in (สมัครบัญชีฟรี)

ใช้ template ใน WebStorm

เอา template ของรายวิชามาบันทึกเป็น template ชื่อ Node-Express-ESM ใน WebStorm สร้างโปรเจกต์งาน error-handler จาก template นั้น ติดตั้ง package และรู้ว่าแต่ละไฟล์มีไว้ทำอะไร

🎯 Learning Objectives
  • บันทึก template Node-Express-ESM และสร้างโปรเจกต์ใหม่จาก template ได้
  • รัน npm install และอธิบายได้ว่าคำสั่งนี้ทำอะไร
  • บอกหน้าที่ของแต่ละไฟล์ใน template และความหมายของ "type": "module"

template คืออะไร ทำไมต้องใช้

template คือโครงโปรเจกต์ตั้งต้นที่มีโฟลเดอร์และไฟล์พื้นฐานเตรียมไว้แล้ว ทุกครั้งที่เริ่มงานใหม่ (แบบฝึกหัดในคาบ หรืองานชิ้นใหม่) ไม่ต้องสร้าง package.json ติดตั้ง Express แล้วสร้างโฟลเดอร์ configs repositories services routes ใหม่ทุกรอบ แค่สร้างโปรเจกต์ใหม่จาก template แล้วเพิ่มเฉพาะส่วนที่ต่างกัน

ในคาบ ขั้นตอนมี 3 ช่วง คือ (1) เอา template ของรายวิชามาเปิดใน WebStorm (2) บันทึกเป็น template ชื่อ Node-Express-ESM (3) สร้างโปรเจกต์งานจริงจาก template นั้น

  2. ดูให้ดีว่าโฟลเดอร์ไม่ซ้อน 2 ชั้น ต้องเปิดเข้าไปแล้วเจอ package.json กับ src ทันที ถ้าเปิดไปเจอโฟลเดอร์ express-template อีกชั้น ให้ใช้โฟลเดอร์ด้านใน

  2. กด Open เลือกโฟลเดอร์ express-template ใน WebstormProjects แล้วกด Select Folder (macOS: Open)

ขั้นที่ 5 — ติดตั้ง package (npm install)

โปรเจกต์ที่สร้างจาก template ไม่มีโฟลเดอร์ node_modules มาให้ พอเปิดโปรเจกต์ใหม่ WebStorm จะเด้งแจ้งเตือน Install dependencies — From package.json มุมขวาล่าง ให้กด Run 'npm install' WebStorm จะอ่าน package.json แล้วติดตั้ง express กับ mysql2 ให้เอง

ถาม: ใช้ VS Code แทน WebStorm ได้ไหม ทำ template ยังไง

VS Code ไม่มีระบบ project template ในตัวแบบ WebStorm วิธีง่ายที่สุดคือเก็บโฟลเดอร์ express-template ไว้ แล้วทุกครั้งที่เริ่มงานใหม่ให้คัดลอกทั้งโฟลเดอร์ไปตั้งชื่อใหม่ แล้วรัน npm install หรือหา extension ที่ทำ template ได้ ใช้ AI ช่วยอธิบายวิธีตั้งค่าได้ แต่อย่าให้ AI ทำงานแทน

"type": "module" ใน package.json

{
  "name": "express-template",
  "type": "module",   // ← บรรทัดนี้ทำให้ใช้ import / export ได้
  "dependencies": {
    "express": "^5.2.1",
    "mysql2": "^3.24.3"
  }
}

Node.js เขียนโมดูลได้ 2 แบบ แบบเก่าคือ CommonJS ใช้ require() กับ module.exports แบบใหม่คือ ES Module (ESM) ใช้ import กับ export บรรทัด "type": "module" บอก Node ว่าโปรเจกต์นี้ใช้แบบ ESM ทั้งโปรเจกต์ (ตัว ESM ในชื่อ template Node-Express-ESM ก็มาจากตรงนี้) ถ้าบรรทัดนี้หายไป ตอนรันจะเจอ SyntaxError: Cannot use import statement outside a module (หมายเหตุ: JSON จริงใส่ comment ไม่ได้ ข้อความ // ← ในกล่องด้านบนใส่ไว้อธิบายเท่านั้น)

sakila คืออะไร

sakila คือฐานข้อมูลตัวอย่างที่ MySQL แจกให้ใช้ฝึก จำลองร้านเช่าหนัง DVD มีทั้งหนัง (film) นักแสดง (actor) ลูกค้า (customer) การเช่า (rental) การจ่ายเงิน (payment) สาขา (store) พนักงาน (staff) และที่อยู่ ซึ่งแยกเป็น address → city → country

sakila มี 16 ตาราง แต่ละตารางคือ resource หนึ่งตัวของ REST API ถ้าจะทำ API ของทั้ง sakila ต้องมีอย่างน้อย 16 resource ในคาบเริ่มจาก resource country (1 ใน 16) เพราะง่ายที่สุด มีแค่ 3 คอลัมน์ (สนุก ๆ: ประเทศไทยใน sakila มีเมืองเดียว)

คอลัมน์ความหมาย
country_idprimary key เป็นตัวเลข auto increment (ฐานข้อมูลออกเลขให้เอง)
countryชื่อประเทศ
last_updateเวลาแก้ไขล่าสุด ฐานข้อมูลใส่ให้เอง
จดไว้ตรงนี้
primary key ของ country ชื่อ country_id ไม่ใช่ id — เดี๋ยวจะได้เจอกับตัวเองตอนทดสอบ repository

สังเกตว่าตาราง city อ้างถึง country ด้วย foreign key ประเทศเดิมใน sakila จึงลบไม่ได้ เพราะยังมีเมืองผูกอยู่ ในบทที่ 4 จะทดลองลบเฉพาะประเทศที่เราเพิ่มเอง

ขั้นที่ 1 — สร้าง Data Source ใน WebStorm

Data Source คือการบอก WebStorm ว่าจะต่อไปที่ MySQL ตัวไหน ด้วย user อะไร เพื่อเปิดดูตารางและรัน SQL ได้จากใน WebStorm เลย

  1. เปิดหน้าต่าง Database: เมนู View → Tool Windows → Database (หรือคลิกไอคอนรูปถังข้อมูลที่แถบด้านข้าง)
  2. กดปุ่ม + → Data Source → MySQL
  1. ถ้าเพิ่งใช้ครั้งแรก ด้านล่างจะมีข้อความ Download missing driver files ให้กดดาวน์โหลด driver ก่อน (ในคาบมีหลายคนติดตรงนี้ ถ้าไม่โหลด Test Connection จะไม่ผ่าน)
  2. กรอก Host = localhost · Port = 3306 · User = root · Password = รหัสผ่าน MySQL ของเครื่องตัวเอง (เครื่องในห้องแล็บใช้รหัสที่อาจารย์แจ้งในคาบ)
  3. ช่อง Database: เครื่องในห้องแล็บมี sakila ติดตั้งไว้แล้ว พิมพ์ sakila หรือกด Ctrl+Space ให้ขึ้นรายชื่อฐานข้อมูลแล้วเลือก sakila · ถ้าเป็นเครื่องตัวเองที่ยังไม่มี sakila ให้ปล่อยว่างไว้ก่อน แล้วทำขั้นที่ 2
  4. กด Test Connection ต้องขึ้นกล่องสีเขียว Succeeded แล้วกด OK

ถ้า Test Connection ไม่ผ่าน ดูกล่อง "ถ้าเจอแบบนี้" ท้ายบท สาเหตุเกือบทั้งหมดคือ MySQL ยังไม่ได้เปิด หรือรหัสผ่านผิด

ขั้นที่ 2 — (เฉพาะเครื่องที่ยังไม่มี sakila) ติดตั้ง sakila

เครื่องในห้องแล็บมีให้แล้ว ข้ามไปขั้นที่ 3 ได้เลย ถ้าเป็นเครื่องตัวเองและรายชื่อฐานข้อมูลไม่มี sakila ให้ติดตั้งตามนี้

2.1 ดาวน์โหลด

  1. เข้าเว็บ https://dev.mysql.com/doc/index-other.html
  2. หัวข้อ Example Databases แถว sakila database ให้กดลิงก์ Zip จะได้ไฟล์ sakila-db.zip
  3. แตก zip จะได้โฟลเดอร์ sakila-db ข้างในมี sakila-schema.sql sakila-data.sql และ sakila.mwb (ไฟล์ .mwb ไม่ได้ใช้)

2.2 รันสคริปต์ sakila (ลำดับสำคัญ)

ต้องรัน sakila-schema.sql ก่อน แล้วจึงรัน sakila-data.sql ไฟล์แรกสร้างฐานข้อมูลกับตาราง ไฟล์ที่สองเติมข้อมูลลงตารางเหล่านั้น ถ้ารันสลับกัน ไฟล์ข้อมูลจะไม่มีตารางให้ใส่ข้อมูลและขึ้น error

  1. ลากโฟลเดอร์ sakila-db มาวางในแถบ Project ของโปรเจกต์ (หรือคัดลอกไปไว้ในโฟลเดอร์โปรเจกต์) จะได้คลิกไฟล์ .sql จาก WebStorm ได้ ใช้เสร็จแล้วลบออกได้ ไม่ต้องส่งไปกับงาน
  2. คลิกขวาที่ sakila-schema.sql → Run 'sakila-schema.sql' (Ctrl+Shift+F10 · ⌃⇧R)
  1. ครั้งแรกจะขึ้นหน้าต่าง Edit Configuration ด้านล่างมีข้อความแดง Error: No configured target data sources แปลว่ายังไม่ได้บอกว่าจะรันสคริปต์นี้ที่ฐานข้อมูลไหน
  1. กดปุ่ม + ใต้หัวข้อ Target data source / schema แล้วเลือก @localhost (Data Source ที่สร้างในขั้นที่ 1)
  1. ช่อง target จะขึ้น @localhost / <unknown> ตัวสีแดง ไม่เป็นไร (ยังไม่ได้เลือก schema และสคริปต์นี้จะสร้างฐานข้อมูล sakila เอง) ข้อความ error ด้านล่างหายไปแล้ว กด Run
  1. ดูที่หน้าต่าง Run ด้านล่าง บรรทัดสุดท้ายต้องเป็น Summary: 46 of 46 statements executed (ใช้เวลาไม่กี่วินาที)

2.3 ให้ Data Source แสดงฐานข้อมูล sakila

หลังรันสคริปต์ ในหน้าต่าง Database จะยังเห็นแค่ @localhost พร้อมป้าย 0 of 5 ยังไม่เห็นตาราง เพราะ Data Source ยังไม่รู้ว่าจะแสดงฐานข้อมูลไหน

  1. คลิกขวาที่ @localhost → Properties (หรือไอคอนเฟืองในหน้าต่าง Database) เพื่อเปิดหน้าต่าง Data Sources and Drivers อีกครั้ง
  2. ช่อง Database พิมพ์ sakila ชื่อ Data Source จะเปลี่ยนเป็น sakila@localhost เอง แล้วกด OK
  3. ถ้ายังไม่เห็นตาราง ให้กดปุ่ม Refresh (⟳) ในหน้าต่าง Database
อีกวิธี: เลือก schema จากป้าย "0 of 5"

คลิกที่ป้าย 0 of 5 ข้างชื่อ @localhost จะมีรายการ schema ให้ติ๊ก เลือก sakila แล้วกด Enter หรือคลิกนอกรายการ

3.1 Error propagation — ส่ง error ขึ้นไปดักจุดเดียว

error เกิดได้ทุกชั้น เช่น router ได้ข้อมูลผิดรูปแบบ service เจอเงื่อนไขไม่ผ่าน หรือ repository หาข้อมูลไม่เจอ ถ้าไม่มีใครดัก error ไว้ในฟังก์ชันที่เกิด มันจะถูกส่งต่อขึ้นไปหาฟังก์ชันที่เรียก ขึ้นไปเรื่อย ๆ ตาม call stack เรียกว่า error propagation

แทนที่จะเขียนดัก error ทีละชั้น (ซ้ำ ๆ และลืมง่าย) เราปล่อยให้ error ไหลขึ้นไปแล้วดักไว้ที่เดียวบนสุด ซึ่งใน Express ก็คือ error middleware ท้าย app.js (เส้นประในแผนภาพบทที่ 0)

ถ้าไหลขึ้นไปจนสุดแล้วยังไม่มีใครดักเลย Node.js จะหยุดโปรแกรมทันที (exit code 1) ถ้าเป็น server แปลว่า API ล่มทั้งตัว ทุกคนใช้ไม่ได้ ลองดูของจริงในหัวข้อถัดไป

3.2 ทดลอง: โปรแกรมที่ไม่ดัก error

3.5 class AppError — error ที่มีโครงเดียวกันทั้งโปรเจกต์

ถ้าทุกคนในทีมสร้าง error เองคนละแบบ บางคนใช้ status บางคนใช้ statusCode ฝั่ง frontend จะอ่านยาก วิธีที่ดีกว่าคือสร้าง class ของเราเองที่สืบทอดจาก Error ทุก error ในโปรเจกต์จะมี field ชุดเดียวกัน ต่างกันแค่ข้อความกับ status code

class นี้อยู่ด้านบนสุดของ test-exception-handling.js แล้ว (ใต้บรรทัด import) ถ้าสร้างไฟล์เองให้พิมพ์เพิ่มตามนี้

class AppError extends Error {
    errors = {404: 'NOT_FOUND', 400: 'BAD REQUEST', 409: 'CONFLICT',
        500: 'INTERNAL SERVER ERROR', 403: 'FORBIDDEN', 401: 'UNAUTHORIZED'}
    constructor(message, statusCode) {
        super(message);                        // ส่ง message ให้ Error (คลาสแม่) เป็นคนเก็บ
        this.statusCode = statusCode;          // เก็บ status code เช่น 404
        this.error = this.errors[statusCode];  // แปลงเป็นชื่อ เช่น 404 → 'NOT_FOUND'
        this.isOperational = true;           // เป็น error ที่คาดไว้แล้ว (ไม่ใช่ bug)
        Error.captureStackTrace(this, this.constructor);
    }
}
  • super(message) — message เป็น field ของคลาสแม่ (Error) ต้องส่งผ่าน super ให้คลาสแม่ตั้งค่าเอง
  • errors — ตารางแปลงเลข status เป็นชื่อที่อ่านเข้าใจ
  • isOperational — ใช้แยก error ที่คาดไว้ (หาข้อมูลไม่เจอ ข้อมูลซ้ำ) ออกจาก bug ในโค้ด
  • Error.captureStackTrace(...) — ให้ stack trace เริ่มจากจุดที่สร้าง AppError ไม่รวมบรรทัดภายใน constructor

ขั้น C — ใน catch ใส่ comment กลับให้ 3 บรรทัด Message / Status / Code แล้วเอา comment ออกจาก 2 บรรทัดของ AppError (ไฟล์จะกลับเป็นแบบเดียวกับใน template) แล้วรัน

} catch (e) {
    // console.log('Message: ', e.message);
    // console.log('Status: ', e.status);
    // console.log('Code: ', e.code);
    // console.log('Stack Trace: ', e.stack);
    const err = new AppError(e.message, 404);

}

3.6 Middleware ของ Express

middleware คือฟังก์ชันที่รับ (req, res, next) Express เรียกมันตามลำดับที่เขียน app.use(...) ไว้ เหมือนด่านตรวจที่ request ต้องผ่านทีละด่าน แต่ละด่านทำอย่างใดอย่างหนึ่ง

  • เรียก next() — ส่ง request ต่อให้ด่านถัดไป
  • เรียก res.json() / res.send() / res.end() — ตอบกลับ client แล้วจบ ไม่ไปด่านถัดไป
// ด่านที่ 1 — พิมพ์ log ทุก request
app.use((req, res, next) => {
    console.log(`${req.method} ${req.url}`)
    next()                      // ส่งต่อด่านถัดไป ถ้าลืม request จะค้าง
})

// ด่านที่ 2 — แปลง body ที่เป็น JSON ให้เป็น req.body
app.use(express.json())

// ด่านที่ 3 — router ของเรา
app.use('/countries', countryRouter)

ลองเพิ่มด่านที่ 1 ไว้ใน app.js ต่อจาก const app = express() แล้ว Rerun ทุกครั้งที่เรียก API จะเห็นบรรทัดเช่น GET /countries ในหน้าต่าง Run

3.7 Error middleware — ฟังก์ชัน 4 พารามิเตอร์

แนวคิด
error middleware

middleware ที่รับ 4 พารามิเตอร์ (err, req, res, next) Express จะเรียกตัวนี้เฉพาะตอนมี error เท่านั้น และข้าม middleware / route ปกติที่เหลือทั้งหมดมาที่นี่ทันที ต้องวางไว้หลังสุด ต่อจาก route ทั้งหมด

Express แยกสองแบบจากจำนวนพารามิเตอร์ ถ้าเขียนแค่ 3 ตัว Express จะมองว่าเป็น middleware ปกติ ดูตัวที่อยู่ท้าย app.js ใน template

app.use((err, req, res, next) => {
    // error จาก MySQL เมื่อข้อมูลซ้ำ (unique / primary key) → แปลงเป็น 409
    if (err.code == "ER_DUP_ENTRY") {
        err.statusCode = 409
        err.code = "CONFLICT"
    }
    // ถ้า error ไม่ได้บอก statusCode มา ถือว่าเป็นความผิดพลาดฝั่ง server (500)
    const statusCode = err.statusCode || 500;
    res.status(statusCode).json({
        status: statusCode,
        error: err.code || 'Server Error',
        message: err.message,
        resource: req.originalUrl,              // URL ที่ถูกเรียก
        timestamp: new Date().toLocaleString()
    });                                         // สังเกต: ไม่ส่ง err.stack ออกไป
})

สังเกตว่าตัวนี้ส่งแค่ message กับ code ไม่ส่ง stack trace ให้ client ตามหลักข้อ 3.2 และใน template บรรทัด app.listen(...) อยู่ก่อน error middleware ก็ยังทำงานได้ เพราะ app.use ทั้งหมดลงทะเบียนเสร็จตั้งแต่ตอนเริ่มโปรแกรม ก่อนมี request แรกเข้ามา สิ่งที่สำคัญคือ error middleware ต้องอยู่หลัง route

ทำไม route ใน template ไม่มี try/catch

route ใน country-route.js (คัดลอกจาก example-route.js) เป็น async function ที่ไม่มี try/catch เลย แต่ error จาก repository ก็ยังไปถึง error middleware ได้ เพราะ template ใช้ Express 5 ซึ่งถ้า async route handler โยน error ออกมา (หรือ Promise ถูก reject) Express 5 จะส่ง error นั้นต่อให้ error middleware ให้เอง ใน Express 4 ต้องเขียนเองแบบแท็บที่สอง

router.get("/:id", async (req, res) => {
    const id = req.params.id
    const object = await service.getObject(id)   // ถ้า throw → ไป error middleware เอง
    res.json(object)
})
router.get("/:id", async (req, res, next) => {
    try {
        const object = await service.getObject(req.params.id)
        res.json(object)
    } catch (err) {
        next(err)    // ต้องส่ง error ให้ error middleware เอง
    }
})

การเรียก next(err) (ส่ง error เข้าไปใน next) คือวิธีบอก Express ตรง ๆ ว่า "มี error ข้ามไป error middleware เลย" ยังใช้ได้ใน Express 5 เช่นกัน (บทที่ 5 ใช้วิธีนี้ดัก path ที่ไม่มีอยู่)

  1. ช่อง Preview ด้านล่างจะแสดง SQL ที่ WebStorm จะรันให้ WebStorm ตั้งชื่อ key ให้เองว่า country_pk ตรวจแล้วกด OK

4.1 สร้าง Collection และ request แรก

Collection คือโฟลเดอร์เก็บ request ใน Postman เก็บไว้แล้วเปิดมากด Send ซ้ำได้ทุกครั้งที่แก้โค้ด ไม่ต้องพิมพ์ URL และ body ใหม่ ต้อง Sign in Postman ก่อน (สมัครบัญชีฟรี) ถ้าไม่ Sign in Postman จะเปิดเป็น Lightweight API Client ส่ง request ได้ครบทุก method เหมือนกัน แต่สร้างหรือบันทึก Collection ไม่ได้

  1. เปิด Postman แล้ว Sign in
  2. กดปุ่ม + เหนือแถบซ้าย → เลือก Collection แล้วตั้งชื่อ INT161 Countries
  1. กด Add request ใต้ชื่อ Collection (หรือคลิกขวาที่ชื่อ Collection → Add request) จะได้แท็บ request ใหม่
  2. ตั้งชื่อ request ที่ breadcrumb ด้านบน (INT161 Countries › ชื่อ request) เช่น Get all countries แล้วใส่ method กับ URL ตามข้อถัดไป
  3. ส่งผ่านแล้วกด Save (Ctrl+S · ⌘S) ถ้ายังไม่ Save แท็บจะมีจุดสีส้ม และแถบซ้ายยังแสดง method เดิม (GET)

หน้าจอ request มีส่วนที่ต้องใช้ 4 จุด ได้แก่ ช่อง method (GET, POST, PUT, DELETE) ช่อง URL แท็บ Body (ใช้กับ POST, PUT) และปุ่ม Send (Ctrl+Enter · ⌘↩) ผลลัพธ์ขึ้นครึ่งล่าง ด้านขวาของแถบผลลัพธ์บอก Status เวลา และขนาด ช่อง URL จะพิมพ์ http://localhost:3000/... หรือ localhost:3000/... เฉย ๆ ก็ได้

ตัวเลือกเสริม: ดัก path ที่ไม่มีอยู่ ให้ตอบเป็น JSON

ในบทที่ 4 เห็นแล้วว่า URL ที่ไม่ตรงกับ route ไหนเลย (เช่น /country) ยังได้หน้า HTML Cannot GET /country เพราะไม่ใช่ error จึงไม่ผ่าน error middleware แก้ได้ด้วย middleware ธรรมดา (3 พารามิเตอร์) อีกตัว วางหลัง route ทั้งหมด แต่ก่อน error middleware request ที่ตกมาถึงตัวนี้คือไม่มี route ไหนรับ จึงสร้าง error 404 แล้วส่งต่อด้วย next(err)

app.use('/countries', countryRouter)

// ดัก path ที่ไม่มี route รองรับ → ส่งต่อเป็น error 404 ให้ error middleware
app.use((req, res, next) => {
    const err = new Error(`Not found: ${req.originalUrl}`)
    err.statusCode = 404
    err.code = "NOT FOUND"     // ให้ช่อง error ตรงกับ 404 ของ repository
    next(err)
})

// error middleware เดิม (4 พารามิเตอร์) อยู่ท้ายสุดเหมือนเดิม
app.use((err, req, res, next) => { /* ... */ })
ผลที่ได้จริงเมื่อ GET /country — status 404 Not Found เป็น JSON
{
    "status": 404,
    "error": "NOT FOUND",
    "message": "Not found: /country",
    "resource": "/country",
    "timestamp": "9/26/2026, 4:21:28 PM"
}

ถ้าไม่ใส่บรรทัด err.code ช่อง error จะขึ้นเป็น "Server Error" (ค่าสำรองใน error middleware) แม้ status จะเป็น 404 ถูกต้อง · PUT /countries ที่ไม่มี id ก็ได้ JSON 404 แบบเดียวกัน

คำถามทบทวน (กดดูคำตอบ)

ลองตอบในใจก่อน แล้วค่อยกดดูคำตอบ

1. error middleware ต่างจาก middleware ปกติตรงไหน

error middleware รับ 4 พารามิเตอร์ (err, req, res, next) ส่วน middleware ปกติรับ 3 ตัว (req, res, next) Express เรียก error middleware เฉพาะตอนมี error เท่านั้น และต้องวางไว้หลัง route ทั้งหมด

2. ทำไมไม่ส่ง stack trace ให้ frontend

stack trace มีข้อมูลภายใน เช่น path ไฟล์บนเครื่อง ชื่อฟังก์ชัน และโครงสร้างโค้ด ผู้ไม่หวังดีเอาไปใช้หาช่องโหว่ได้ และผู้ใช้ทั่วไปก็อ่านไม่เข้าใจ ส่งแค่ code กับ message ที่อ่านเข้าใจก็พอ stack trace ไว้ดูใน log ฝั่ง server

3. ทำไม route ใน template ไม่ต้องมี try/catch

template ใช้ Express 5 ซึ่งถ้า async route handler โยน error หรือ Promise ถูก reject จะส่ง error ต่อให้ error middleware ให้เอง ใน Express 4 ต้อง try/catch แล้วเรียก next(err) เอง

4. ถ้าไม่มี if (err.code == "ER_DUP_ENTRY") ใน error middleware การ POST ชื่อซ้ำจะได้ status อะไร และทำไมถึงผิดความหมาย

ได้ 500 เพราะ error จาก MySQL ไม่มี statusCode จึงตกไปที่ค่าเริ่มต้น || 500 ซึ่งผิดความหมาย 500 แปลว่า server พัง แต่ความจริงคือ client ส่งข้อมูลที่ซ้ำกับของเดิม ควรเป็น 409 Conflict

5. GET /countries/1 ได้ 500 พร้อม Unknown column 'id' in 'where clause' ต้องแก้ที่ไฟล์ไหน

src/repositories/country-repo.js เปลี่ยน WHERE id = ? เป็น WHERE country_id = ? ให้ครบทั้ง 3 บรรทัด (FIND_ONE, UPDATE, REMOVE) แล้ว Rerun

6. 401 กับ 403 ต่างกันอย่างไร

401 Unauthorized = ยังไม่รู้ว่าเป็นใคร (ไม่ได้ล็อกอิน / ไม่มี token) · 403 Forbidden = รู้แล้วว่าเป็นใคร แต่คนนี้ไม่มีสิทธิ์ทำสิ่งนั้น เช่นล็อกอินแล้วแต่ไม่ใช่ admin

7. ทำไมรันแอปขึ้นข้อความ listening ได้ ทั้งที่รหัสผ่าน MySQL ผิด

connection pool ของ mysql2 ยังไม่ต่อฐานข้อมูลจริงตอนเริ่มแอป จะต่อตอนมี query แรก error เรื่องรหัสผ่านจึงโผล่ตอนเรียก endpoint ครั้งแรก ไม่ใช่ตอน Run

8. POST ใน Postman แล้ว req.body เป็น undefined ควรตรวจอะไรบ้าง

(1) ใน Postman เลือก Body → raw → JSON แล้วหรือยัง (2) ใน app.js มี app.use(express.json()) และอยู่ก่อน app.use('/countries', ...) หรือไม่
