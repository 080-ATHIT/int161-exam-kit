# INT161 Exam Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Ship a private GitHub repository containing a real MySQL reference app, Thai offline documentation, adaptation recipes and verified exercises.
**Architecture:** One ESM Express app in the teacher's -$id folder convention, explicit routes/services/repositories/mappers, independent scripts for read-only diagnostics and guarded practice DB initialization/tests. Markdown is the documentation source; one generated HTML file is the offline reading copy.
**Tech Stack:** JavaScript ESM, Express 5, mysql2/promise, http-status, node:test; existing local Node/MySQL.
**Spec:** ../specs/2026-10-21-int161-exam-kit-design.md (approved for implementation by user's request to create GitHub).

## Global Constraints
- Runtime dependencies: express, mysql2, http-status; no ORM, Docker, TypeScript or new frontend framework.
- Static student base path; sample identity only; no real credentials in Git/ZIP/log.
- MySQL persistence must be tested; simulator-only results are insufficient.
- Practice mutations require int161_practice_ database prefix plus kit marker; no automatic exam-template overwrite.
- No network needed after preparing dependencies and local services; Thai docs, macOS-first verification.
- Publication authorized by current user request; create private repo Phakinza007/int161-exam-kit.

## Review Focus
- Arbitrary/missing/duplicate query values: reject invalid pagination and preserve normalized limits.
- Unchanged update: return existing record, not a false 404.
- String/composite identifiers: preserve strings and require both components.
- MySQL data types: exact numeric price, date-only releaseDate and ISO timestamps.
- Wrong database: all automatic mutating tests/init must reject non-practice targets before changes.
