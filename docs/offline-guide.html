INT161 Exam Kit

ชุดฝึก Node.js ESM + Express 5 + MySQL พร้อมคู่มือภาษาไทยอ่านออฟไลน์

เริ่มที่ START-HERE.th.md หรือเปิด คู่มือ HTML หลังดาวน์โหลดลงเครื่อง

  • ตัวอย่าง CRUD จริง: reference-app/src/ แยก route → service → repository และ mapper
  • แนวทำข้อสอบและ Contract Sheet
  • CRUD ทีละชั้น, Pagination / DTO / JOIN
  • Exception / คีย์แบบอื่น
  • ดัดแปลง teacher template
  • แก้ปัญหา / เตรียมออฟไลน์ / ส่งงาน
  • ตัวอย่างเปลี่ยนโจทย์, โจทย์ฝึกทำเอง
  • ผลตรวจจริงและข้อจำกัด

ตัวอย่างนี้สร้างเพื่อฝึก ไม่ใช่ข้อสอบจริงหรือเฉลยที่อาจารย์รับรอง ใช้ข้อมูลสมมติทั้งหมด ไม่รวมเอกสารรายวิชาและ ZIP ของอาจารย์ใน repo นี้

ต้องติดตั้ง Node >=22.9 และ MySQL ที่เปิดใช้งานแล้ว เตรียม npm ci ขณะยังใช้อินเทอร์เน็ตได้ node_modules ไม่รวมใน ZIP; ไฟล์ package-lock.json อย่างเดียวไม่ทำให้ติดตั้งออฟไลน์ได้

เริ่มตรงนี้: INT161

เป้าหมายคืออ่านสเปกแล้วแก้ template ของอาจารย์ได้ด้วยตัวเอง ใช้ kit นี้ฝึกก่อนสอบและเป็นเอกสารออฟไลน์ตามกติกาที่อาจารย์อนุญาต

1. เตรียมเครื่องขณะมีอินเทอร์เน็ต

ต้องมี Git, Node >=22.9 และ MySQL เปิดอยู่ repo เป็น private ต้องใช้บัญชีที่มีสิทธิ์เข้าถึง

git clone https://github.com/Phakinza007/int161-exam-kit.git
cd int161-exam-kit
npm ci
cp .env.example .env

แก้ .env ให้ตรง MySQL ของเครื่อง: DB_HOST, DB_PORT, DB_USER, DB_PASSWORD ห้าม commit ไฟล์นี้ ชื่อฐานฝึกใช้ int161_practice_catalog และ TEST_DB_NAME=int161_practice_tests หากบัญชีไม่มีสิทธิ์ CREATE DATABASE ให้ผู้ดูแลสร้างฐานเฉพาะสำหรับฝึกก่อน และดูคำอธิบาย marker ในคู่มือออฟไลน์ อย่าใส่ฐานงานจริง

npm run doctor
npm run db:init
npm start

เปิด http://127.0.0.1:3000/api/demo001/products?page=1&limit=10 อีก terminal รัน npm test (สร้างฐานทดสอบแยกและเขียน/ลบเฉพาะข้อมูลฝึก) Ctrl+C หยุด server

doctor ตรวจอย่างเดียว ไม่สร้างฐาน db:init สร้างฐานฝึกที่ยังไม่มีพร้อม marker; ถ้าฐานชื่อเดียวกันมีอยู่แต่ไม่มี marker จะปฏิเสธ ไม่ต้องเติม marker ลงฐานที่ไม่รู้ที่มา ให้เลือกชื่อฝึกใหม่ที่ยังไม่มี เช่น int161_practice_my_catalog

2. อ่านตามลำดับนี้

  • Contract Sheet: จด path, body, DTO, status, pagination จากโจทย์จริง
  • CRUD: ตาม request จาก route ลง SQL แล้วกลับเป็น DTO
  • Pagination และ DTO
  • Error, string key, composite key
  • เปลี่ยนตัวอย่าง products เป็น books
  • ทำโจทย์เองโดยไม่เปิดเฉลย
  • ย้ายไป template และ เตรียมก่อนตัดเน็ต

อ่านสรุปอย่างเดียวไม่พอ ต้องลอง POST → GET → PUT → DELETE และดูแถวใน MySQL จริง

3. ไฟล์ที่หยิบใช้

  • requests/catalog.http: เปิดด้วย REST Client ที่ติดตั้งไว้แล้ว หรืออ่านแล้วใช้ curl
  • requests/curl.sh: ชุด smoke ที่สร้างและลบเฉพาะ product ของตัวเอง รัน sh requests/curl.sh
  • requests/postman.json: import เป็น collection; ไม่ต้องใช้ cloud account เพื่อส่ง localhost requests
  • recipes/: ตัวอย่าง response W6, pagination แบบเลือกใช้ และคีย์ string/composite อ่าน import และปรับ path ให้ตรงโครงงาน
  • docs/offline-guide.html: เปิดตรงจาก Finder ได้ ไม่โหลด CDN/ฟอนต์/API ภายนอก

4. ขอบเขตสอบจากประกาศ

ทฤษฎี 52 ข้อ 50 คะแนน เวลา 1 ชั่วโมง ปิดหนังสือ ใช้ดินสอ ครอบคลุมทุกหัวข้อบรรยาย ภาคปฏิบัติ 6 ข้อ: 1 Create, 3 Read, 1 Update, 1 Delete เน้น CRUD, DTO, Pagination, Exception Handling คะแนนดิบ 110 คิดเต็ม 100

Response ตัวอย่าง W8-like

{"success":true,"data":[],"pagination":{"total":0,"page":1,"limit":10,"totalPages":0,"hasNextPage":false,"hasPrevPage":false},"timestamp":"2026-10-21T00:00:00.000Z"}

นี่เป็น contract ของ kit ที่อิงแนว Week08 ต้องเทียบไฟล์สเปกของตัวเองอีกครั้ง ตัวอย่าง W6 ใช้ status:'success' / status:'error' ดู recipes/w6-response.js; เปลี่ยน success helper และ error handler ให้ตรงกันทั้งคู่

นโยบาย input ของ kit

POST/PUT products รับ snake_case: sku,name,brand_id,category,price บังคับ; ram_gb,storage_gb,color,stock_quantity,status,release_date เป็นตัวเลือก PUT ใช้ full body เช่น POST ฟิลด์ที่ไม่รู้จักถูกละทิ้ง ไม่อนุญาตเขียน id หรือ internal_cost ผ่าน API

price ต้องเป็น JSON number >=0 สูงสุด 99999999.99 ทศนิยมไม่เกินสองตำแหน่ง; brand_id เป็นจำนวนเต็มบวก; stock เป็นจำนวนเต็มไม่ติดลบ; release_date เป็นวันที่จริง YYYY-MM-DD หรือ null นโยบายนี้เป็นของชุดฝึก หากโจทย์อนุญาตค่าต่างกันต้องแก้ validation

ชื่อ product/sku/category ห้ามว่างหลัง trim สถานะเริ่ม AVAILABLE stock เริ่ม 0 ฟิลด์ nullable เริ่ม null แยกกรณี missing/null/0 อย่าใช้ value || default เมื่อ 0 เป็นค่าที่ถูก

เช็กให้เข้มกว่าตัว runner

เขียน assertion ของตัวเองตามสเปก ถ้ารันเนอร์รับ DELETE ได้ทั้ง 200/204 หรือ duplicate ได้ทั้ง 400/409 การผ่าน runner ไม่พิสูจน์ว่าตรงข้อความโจทย์ ตรวจ status/body/ชนิดข้อมูล/ชื่อ key ด้วยตาและ request เพิ่มเติม

CRUD ทีละชั้น

เปิดไฟล์ตามเส้นทางนี้: reference-app/src/app.js → routes-$id/catalog-route.js → services-$id/catalog-service.js → repositories-$id/catalog-repository.js → mappers-$id/product-mapper.js

Route และ async

app.js รับ db pool แล้วประกอบ service/repository ติด router ที่ /api/${studentId} โดย studentId เป็นค่าจาก config ตอนเริ่มโปรแกรม express.json() ต้องอยู่ก่อน router และ error handler อยู่ท้ายสุด

Express 5 ส่ง rejected Promise ของ async handler ไป error middleware ได้ Express 4 ต้องใช้ try/catch + next(err) หรือ wrapper; ตรวจเวอร์ชันก่อนคัดลอก

1C: Create

route รับ req.body → service ตรวจ/allowlist input → ตรวจ SKU ซ้ำ → repository INSERT → ใช้ result.insertId เฉพาะ auto increment numeric key → SELECT ใหม่ด้วย JOIN → detail DTO → 201

DB UNIQUE ยังจำเป็นแม้เช็กก่อน INSERT เพราะ request พร้อมกันอาจผ่าน precheck ทั้งคู่ ห้ามใช้ SELECT MAX(id) หาว่าตนสร้างแถวไหน

3R: Read

  • รายการ brands: SELECT list ตามลำดับแน่นอน
  • รายการ products: query parser → LIMIT/OFFSET และ COUNT → summary DTO + metadata
  • รายละเอียด: find by key พร้อม JOIN → ถ้าไม่พบ throw 404 ก่อนเข้า mapper

โจทย์จริงอาจจัด 3R ต่างกัน ให้ดู endpoint ของข้อสอบ ไม่มีหลักประกันว่าจะใช้ชื่อ resource เหมือน kit

1U: Update

ตรวจว่ามีแถวก่อน → validate full body → ถ้า SKU ของอีก id ซ้ำตอบ 409 → UPDATE ด้วย WHERE id=? → อ่านแถวกลับ ตอบ 200

การส่งค่าเดิมทุกฟิลด์เป็น update ที่ถูกต้อง อย่าใช้ changedRows===0 ตัดสินว่าไม่มีแถว เพราะอาจมีแถวแต่ค่าไม่เปลี่ยน

1D: Delete

ตรวจแถว → DELETE WHERE id=? → ตรวจ affectedRows → 204 .end() โดยไม่ส่ง JSON ถ้าสเปกเป็น W6 ให้ส่ง 200 พร้อม envelope ตามโจทย์ หาก FK อ้างอิงอยู่ให้ปล่อย error เข้าตัวแปลงกลาง

SQL ที่ต้องเขียนเองได้

SELECT id, sku, name FROM products ORDER BY id LIMIT ? OFFSET ?;
SELECT COUNT(*) AS total FROM products;
SELECT p.id, p.name, b.name AS brand_name
FROM products p JOIN brands b ON b.id=p.brand_id WHERE p.id=?;
INSERT INTO products (sku,name,brand_id,category,price) VALUES (?,?,?,?,?);
UPDATE products SET name=?, price=? WHERE id=?;
DELETE FROM products WHERE id=?;

ส่ง values ผ่าน parameter binding ไม่ต่อ string จาก request ลง SQL ตัวอย่าง repo ใช้ query('INSERT ... SET ?', [data]) กับ object ที่ service เลือกฟิลด์ไว้แล้ว ซึ่ง mysql2 .query รองรับ อย่าสลับเป็น .execute แล้วส่ง object แบบเดียวกัน

ทดสอบด้วยข้อมูลของตัวเอง ดู SQL persistence หลัง POST/PUT และ GET หลัง DELETE ไม่ถือว่า response อย่างเดียวพิสูจน์การบันทึกแล้ว

Pagination, DTO และ JOIN

Pagination

kit กำหนด page เริ่ม 1, limit เริ่ม 10 สูงสุด 100 รับ string ตัวเลขจำนวนเต็มบวกเท่านั้น หากส่งผิดหรือส่งซ้ำตอบ 400 ตัวอย่าง page=1.5, page=0, page=abc, limit=0, page=1&page=2

const limit = Math.min(requestedLimit, 100);
const offset = (page - 1) * limit;
const totalPages = Math.ceil(total / limit);

ต้องคำนวณ offset หลัง cap limit ใช้ ORDER BY ที่แน่นอน และ COUNT ใช้ filter เดียวกับรายการ กรณีไม่มีข้อมูล total=0, data=[], totalPages=0 ห้าม fallback เป็นจำนวนอื่นด้วย || หน้าเกินสุดท้ายยัง 200 พร้อม [] และ total จริง

kit ไม่มี search/filter; ถ้าโจทย์เพิ่ม ต้องแก้ทั้ง list และ count ให้ตรงกัน นโยบายไม่ส่ง page/limit คือยังแบ่งหน้าด้วย default หากโจทย์ต้องคืนทั้งหมดเมื่อไม่มี query ใช้ recipes/optional-pagination.js แล้วแยก SQL แบบไม่มี LIMIT ให้ครบ ไม่ใช่แก้แค่ parser

DTO allowlist

summary มี 7 ฟิลด์: id, sku, name, brandId, category, price, status

detail มี 13 ฟิลด์: id, sku, name, brandId, brandName, category, price, ramGb, storageGb, color, stockQuantity, status, releaseDate

อย่าใช้ {...entity} เพราะอาจหลุด internal_cost และชื่อคอลัมน์ DB ไม่ตรง API DTO แปลง snake_case → camelCase ด้วย mapping ชัดเจน เช็ก null ก่อน mapper เพื่อให้ missing เป็น 404

mysql2 มักคืน DECIMAL เป็น string จึงใช้ Number(entity.price) ใน DTO ตาม contract นี้ DATE ใช้ dateStrings เพื่อรักษาวันเดิม releaseDate เป็น YYYY-MM-DD หรือ null; timestamp ของ envelope เป็น ISO UTC ไม่ใช่ DATE

JOIN

products มี brand_id แต่ detail ต้อง brandName จึงต้อง JOIN brands แล้ว alias b.name AS brand_name ห้ามเดาหรือ hardcode ชื่อ brand

ถ้าใช้ LEFT JOIN ต้องกำหนดว่าค่าไม่มี brand เป็น null หรือ error ตามโจทย์ ใน kit FK บังคับ brand และใช้ INNER JOIN

Numeric key

products.id เป็น auto increment ต้องตรวจ positive safe integer ก่อน Number ไม่ใช้ parseInt ที่ยอมรับ 12abc การสร้างอ่าน insertId

String key

tags.code เป็น VARCHAR เช่น NA, CS_01 ต้องคง string ไม่ Number/parseInt และการสร้างอ่านกลับด้วย code ที่ส่งเข้า ไม่ใช้ insertId ตัวอย่างจริงใน routes/service/repo และสูตรสั้น recipes/string-composite-repository.js

Composite key

product_tags มี PRIMARY KEY(product_id, tag_code) จึงต้อง bind ทั้งคู่ใน WHERE และ route เช่น DELETE /products/7/tags/DEMO อย่าลบด้วย product_id อย่างเดียวเพราะจะลบหลายความสัมพันธ์

Entry point ต้องแก้ด้วย

app.js ของ kit export factory จึงไม่เปิด port ด้วยตัวเอง สร้าง src/server.js ใน template ดังนี้ (หลังตรวจ config และสิทธิ์ DB ตามโจทย์):

import {createApp} from './app.js';
import {loadSettings} from './configs-$id/settings.js';
import {createDb} from './configs-$id/db-config.js';
const config=loadSettings();
const db=createDb(config);
await db.query('SELECT 1');
createApp({db,studentId:config.studentId,name:config.name,key:config.key})
  .listen(config.appPort,'127.0.0.1');

ตั้ง start เป็น node --env-file-if-exists=.env src/server.js ใน teacher package.json รักษา dependency ของอาจารย์ไว้ จากนั้นแก้ schema, repository, service, mapper, routes ให้ตรงข้อสอบทั้งหมด

server.js ของ reference-app ตรวจ marker ฐานฝึกและ import script นอก src ห้ามคัดลอกตัวนั้นตรง ๆ เข้า template สอบ ตัวอย่าง entry ด้านบนไม่พึ่ง marker และเชื่อม DB ที่ตั้งไว้จริง จึงต้องตรวจ DB_NAME ให้ถูกก่อนทำ request ที่แก้ข้อมูล ไม่ใช้ db:init หรือ npm test ของ kit กับฐานสอบ

สิ่งที่ต้องเปลี่ยนทุกครั้ง

  • static STUDENT_ID, name/key ที่โจทย์ของตัวเองกำหนดใน .env เท่านั้น
  • DB config / SQL schema / table / columns / PK / FK / UNIQUE
  • input และ validation รวม partial/full PUT
  • list/detail DTO, aliases, type number/date/null
  • envelope, status, pagination policy และ endpoint ทั้งหมด
  • requests และ assertions ตามสเปก ไม่ใช้ expected output เก่าทั้งชุด

1. Schema

CREATE TABLE books (

);

ทำเฉพาะฐานฝึกที่แยกไว้ เทสต์สร้างตารางนี้ใน TEST_DB_NAME หลังตรวจ marker แล้ว ลบเฉพาะแถวที่ test สร้าง

2. Repository → service → mapper → route

เปิด practice/worked-example/repository.js: find รับ code string, create อ่านกลับด้วย book_code, update WHERE book_code ไม่ใช้ insertId หรือ numericId และมี ORDER BY / COUNT

เปิด service.js: บังคับ title/author/fee ตรวจ string PK แยกจาก numeric product ID การ update ยึด code ใน URL ไม่เปลี่ยนตาม body ตรวจว่ามีแถวก่อนจึงยอมรับการส่งค่าเดิม

เปิด mapper.js: สร้าง allowlist ใหม่ code/title/fee และ author เฉพาะ detail แปลง DECIMAL เป็น number ไม่เหลือฟิลด์ product

เปิด app.js: base คงที่ demo002; ส่ง success และ error แบบ W6 ทั้งคู่ DELETE200 มี body; pagination ยังคง default1/10/max100 แบบ kit

โจทย์ฝึกทำเอง: Departments

โจทย์นี้แต่งเพิ่มเพื่อฝึก ไม่ใช่โจทย์อาจารย์ ไม่มี implementation เฉลยใน repo ให้ใช้ template เปล่าและคู่มือ โดยเริ่มจาก Contract Sheet

Schema และ contract

สร้าง departments: dept_code VARCHAR(12) PRIMARY KEY, dept_name VARCHAR(100) NOT NULL UNIQUE, budget DECIMAL(10,2) NOT NULL DEFAULT 0 และ internal_note TEXT nullable ที่ห้ามส่งผ่าน API

base path เป็นค่าคงที่ /api/รหัสของคุณ ใช้ response {status:'success',data:...} และ error {status:'error',error:{code,message}}

  • POST /departments รับ dept_code,dept_name,budget; code ห้ามว่างและคง string, budget number>=0 สูงสุด99999999.99 สองตำแหน่ง ตอบ201 detail; duplicate code หรือ name409
  • GET /departments?page=1&limit=5 ค่าเริ่ม1/5 สูงสุด20 ตรวจ invalid/duplicatequery400; list DTO code,name; pagination มี total/page/limit/totalPages/hasNextPage/hasPrevPage
  • GET /departments/:code detail DTO code,name,budget; missing404
  • GET /departments/:code/summary ส่งเฉพาะ code,name; missing404
  • PUT /departments/:code รับ dept_name,budget เปลี่ยน PK ไม่ได้ ค่าเดิม200; missing404; duplicate name409
  • DELETE /departments/:code ตอบ200 JSON data เป็น {code,deleted:true}; missing404

ตรวจว่าทำเองได้

เริ่มโดยปิดโค้ด products/books แล้วเขียน SQL/mapper/service/route เอง เช็ก code=CS01 ไม่กลายเป็น NaN, priceเป็นnumber, internal_noteไม่หลุด, countตรงทุกหน้า, budget0ไม่หาย และ PUTค่าเดิมไม่404 สร้างอย่างน้อย7แถวเพื่อมีหน้าที่สอง ลบข้อมูลที่ตนสร้างแล้วตรวจในDB

เก็บ request และผลที่คาดหวังเองให้ครบ6ข้อ หากติด ให้ดูคู่มือเฉพาะหัวข้อแล้วกลับมาเขียนใหม่ บันทึกจุดที่ยังต้องเปิดตัวอย่าง การตรวจข้อนี้ต้องทำโดยผู้เรียน ยังไม่ได้รับรองว่าผ่านจาก automated tests ของ kit
